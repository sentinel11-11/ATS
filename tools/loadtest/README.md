# Load-test инструментарий ATS v2 (этап F аудита)

Воспроизводимые сценарии без внешних зависимостей (только stdlib).

> **Статус: инструменты подготовлены, прогоны на стенде/проде НЕ проводились.**
> Цифры ниже — smoke-проверка работоспособности самих скриптов в однопроцессной
> песочнице (sim-провайдер, временная БД). Это НЕ заявление о производительности.
> Реальные отчёты появятся после запуска на выделенном стенде (ROADMAP, фаза 2).

## Сценарии

### 1. API: пользователи + сессии + поллинг

```bash
python3 tools/loadtest/api_load.py --users 5000 --sessions 500 --pollers 50 \
    --duration 120 --report tools/loadtest/report-api.json
# self-hosted: поднимает чистый экземпляр на sim во временной БД (порт 19124).
# Против стенда: --url http://стенд:9124 (ОПАСНО на проде — создаёт пользователей!)
```

Целевые ориентиры для первого стенда (предложение, не критерий «зелёного»):
5 000 пользователей, 500 активных сессий, p95 GET-API < 300 мс,
error rate < 0.1%, отсутствие роста RSS в процессе прогона.

### 2. SSE: одновременные EventSource-подключения

```bash
python3 tools/loadtest/sse_load.py --clients 100 --duration 60 \
    --report tools/loadtest/report-sse.json
```

Проверяет: подключение по одноразовым билетам (как реальный UI), задержку
первого байта, keepalive, живучесть соединений. Цель: 100 соединений без
разрывов, подключения укладываются в секунды.

### 3. Телефония (не реализовано скриптом)

Симулятор каналов 10/25/50/100 и live-стенд — отдельно, по чек-листам
`LIVE_TEST_MEGAFON.md` / `docs/MULTICOM_SETUP_STEPS.md`, в рамках
ограничений оператора. Заявлений о параллельных звонках без этих прогонов
не делается.

## Smoke-результаты (песочница, НЕ ёмкость)

| Сценарий | Параметры | Результат |
|---|---|---|
| api_load | 200 пользователей, 50 сессий, 20 поллеров, 30 с | см. `report-api-smoke.json` (репозиторий не фиксирует «прод»-цифры: они зависят от машины) |
| sse_load | 30 клиентов, 20 с | см. `report-sse-smoke.json` |

Smoke доказывает только то, что сценарии выполняются и собирают метрики.
Сравнивать машины/версии — только по идентичным прогонам на одном стенде.

## Правила честности (из аудита, этап F)

- не заявлять «выдержит N пользователей» без отчёта с этого стенда;
- не экстраполировать sim-результаты на живую телефонию;
- фиксировать версию, окружение, параметры и полное время прогона в отчёте;
- p95/p99, error rate, число соединений — обязательно; «тест зелёный» без
  метрик не принимается.
