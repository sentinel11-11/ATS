# ATS v2 — развёртывание на сервере (подробная инструкция)

Продукт готов к продакшену и рассчитан на один Linux-сервер (или Windows Server).
Он самодостаточен: один процесс, стандартная библиотека Python, данные в одной
папке (`data_v2/`). Ниже — полный путь от «купил сервер» до работающего HTTPS.

> Инструкция написана для **Ubuntu 24.04 LTS** (подойдут 22.04 / Debian 12).
> Вариант для Windows Server — в конце документа.

---

## 0. Что нужно купить / подготовить

| Что | Минимально | Комфортно |
|---|---|---|
| VPS (Linux) | 1 vCPU, 1 ГБ RAM | 2 vCPU, 2 ГБ RAM |
| Диск | 20 ГБ | 40+ ГБ (записи разговоров ~1–2 МБ/мин) |
| Домен | желателен | обязателен для HTTPS и вебхука UIS |
| ОС | Ubuntu 24.04 LTS | — |
| Python | 3.10+ | ставится из репозитория ОС |

Зачем нужен **домен + HTTPS**:
1. браузерные уведомления операторам (Notification API) работают только на
   HTTPS (или localhost) — без домена колокольчик у операторов не зазвонит;
2. вебхук UIS должен быть по публичному HTTPS-адресу;
3. интерфейс по паролю нельзя гонять по открытому HTTP.

Схема после установки:

```
Интернет / операторы
        │  https://ats.example.com  (443)
        ▼
     nginx (HTTPS, Let's Encrypt)
        │  http://127.0.0.1:9124
        ▼
  ATS v2 (python -m app.run)  ──▶ data_v2/ (БД, записи, бэкапы)
```

## 1. Базовая настройка сервера

Подключитесь по SSH и выполните:

```bash
# обновление ОС
sudo apt update && sudo apt upgrade -y

# часовой пояс сервера = локальное время расписания звонков
sudo timedatectl set-timezone Europe/Moscow

# пакеты: python3, venv, git, nginx
sudo apt install -y python3 python3-venv git nginx

# отдельный пользователь для ATS (без прав root)
sudo useradd -r -m -d /opt/ats -s /usr/sbin/nologin ats
```

---

## 2. Установка кода

Код можно получить двумя способами:

**А. Через git (рекомендуется — легко обновляться):**
```bash
sudo mkdir -p /opt/ats && sudo chown ats:ats /opt/ats
sudo -u ats git clone https://github.com/sentinel11-11/ATS.git /opt/ats/app
cd /opt/ats/app
sudo -u ats python3 -m venv venv
```

**Б. Переносом с вашего компьютера:** скопируйте папку проекта на сервер
(например, через `scp -r` или WinSCP) в `/opt/ats/app`, затем то же самое:
```bash
cd /opt/ats/app
sudo -u ats python3 -m venv venv
```

Дополнительные пакеты ставить не нужно — только стандартная библиотека.

---

## 3. Каталог данных (вне кода!)

Данные (БД SQLite, записи, CRM-выгрузка, бэкапы) держим **отдельно от кода** —
тогда обновления кода никогда не трогают данные:

```bash
sudo mkdir -p /var/lib/ats
sudo chown ats:ats /var/lib/ats
```

Если вы переносите **существующую базу с рабочего компьютера** (там была
`data_v2/ats.db` с контактами/кампаниями/пользователями) — скопируйте её:

```bash
# с Windows на сервер:  scp -r data_v2/* user@server:/tmp/ats_data/
sudo cp -r /tmp/ats_data/* /var/lib/ats/
sudo chown -R ats:ats /var/lib/ats
```

Если сервер **новый и пустой** — просто запустите один раз «инициализацию»:

```bash
cd /opt/ats/app
sudo -u ats env ATS_DATA_DIR=/var/lib/ats ATS_ADMIN_PASSWORD='СложныйПароль123!' \
    ./venv/bin/python -m app.run --init-only
```

Что произойдёт:
- создастся `/var/lib/ats/ats.db` и файл учётных данных
  `/var/lib/ats/initial_credentials.txt` (логин `admin` + заданный пароль);
- создастся только администратор (никаких демо-операторов и номеров-заглушек);
- пароль админа позже можно сменить командой
  `--admin-password "Новый"` (с опцией `--init-only` — только сменить и выйти).

## 4. Служба (systemd) — чтобы работала всегда и поднималась сама

Создайте файл `/etc/systemd/system/ats.service`:

```ini
[Unit]
Description=ATS v2 Dispatcher
After=network.target

[Service]
Type=simple
User=ats
WorkingDirectory=/opt/ats/app
Environment=ATS_DATA_DIR=/var/lib/ats
ExecStart=/opt/ats/app/venv/bin/python -m app.run --host 127.0.0.1 --port 9124
Restart=always
RestartSec=3

# безопасность
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

> `--host 127.0.0.1`: приложение слушает только localhost, наружу его
> «выставляет» nginx. Порт 9124 не нужно открывать в файрволе.

Включите и запустите:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ats
sudo systemctl status ats        # должно быть active (running)
```

Логи службы: `journalctl -u ats -f` (там же будут сообщения о звонках/ошибках).

## 5. nginx + HTTPS (Let's Encrypt)

Настройте DNS: запись `A` для домена, например `ats.example.com` → IP сервера.

### 5.1. Конфигурация nginx

Создайте `/etc/nginx/sites-available/ats`:

```nginx
# перенаправление HTTP → HTTPS
server {
    listen 80;
    server_name ats.example.com;   # ← ваш домен

    location /.well-known/acme-challenge/ { root /var/www/html; }
    location / { return 301 https://$host$request_uri; }
}

server {
    listen 443 ssl http2;
    server_name ats.example.com;   # ← ваш домен

    ssl_certificate     /etc/letsencrypt/live/ats.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/ats.example.com/privkey.pem;

    # приложение
    location / {
        proxy_pass http://127.0.0.1:9124;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
    }

    # события в реальном времени (SSE) — без буферизации, иначе «зависнет»
    location /api/v2/events {
        proxy_pass http://127.0.0.1:9124;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header Connection "";
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 3600s;
    }

    # загрузка записей разговоров (файлы до 50 МБ)
    location /api/v2/calls/recording {
        proxy_pass http://127.0.0.1:9124;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        client_max_body_size 60m;
    }

    client_max_body_size 60m;
}
```

Включите сайт:

```bash
sudo ln -s /etc/nginx/sites-available/ats /etc/nginx/sites-enabled/ats
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

### 5.2. Сертификат

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d ats.example.com     # ← ваш домен
# автообновление сертификата уже настроено certbot'ом:
sudo systemctl list-timers | grep certbot
```

### 5.3. Файрвол

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'      # 80 + 443
sudo ufw enable
```

## 6. Проверка после установки

1. Откройте `https://ats.example.com` → экран входа.
2. Войдите `admin` / заданный пароль.
3. В «Настройках» смените пароль, заведите операторов
   («Пользователи и операторы»), добавьте номера Caller ID («Пул номеров»).
4. Индикатор «обновление в реальном времени» внизу слева должен гореть зелёным
   (значит, SSE через nginx работает).

## 7. Подключение реальной телефонии (UIS / Asterisk)

Работать «вхолостую» можно на провайдере `sim` (тест без оборудования).
Для реальных звонков:

**UIS (МегаФон «Ювис» Call API):**
1. В интерфейсе: «Настройки → Провайдеры и интеграции» — заполните `uis`:
   `api_url`, `api_key`, при необходимости `number_pool_api`.
2. Там же укажите секрет вебхука (`uis.webhook_secret`).
3. В личном кабинете UIS пропишите адрес вебхука:
   `https://ats.example.com/api/v2/webhooks/uis`
   (заголовок `X-UIS-Secret` = ваш секрет).
4. Перезапустите службу: `sudo systemctl restart ats`.
5. Добавьте реальные номера в «Пул номеров» (провайдер `uis`).

**Asterisk (AMI):**
1. Сервер ATS должен иметь сетевой доступ к PBX (порт 5038).
2. Заполните `ami`: host/port/user/secret в «Провайдеры и интеграции».
3. Перезапустите службу. Звонки пойдут через SIP-транк PBX.

Если провайдер недоступен — движок сам откатится на `sim` и продолжит работу
(звонки будут записываться как симулированные; это видно по панели sim).

## 8. Резервное копирование

**Встроенное:** при каждом запуске службы делается авто-бэкап БД в
`/var/lib/ats/backups/ats-*.db` (хранятся последние 12).

**Внешний ежедневный бэкап** — добавьте в cron (`sudo crontab -e`):

```cron
# 03:10 ежедневно — архив всех данных ATS за пределы сервера
10 3 * * * tar -czf /backup/ats-$(date +\%F).tar.gz -C /var/lib/ats . && \
          find /backup -name 'ats-*.tar.gz' -mtime +30 -delete
```

> Папку `/backup` лучше держать на отдельном диске/хранилище (или настроить
> синхронизацию в объектное хранилище). Записи разговоров — единственные
> «тяжёлые» файлы (в `/var/lib/ats/recordings/`).

## 9. Обновление ATS

```bash
cd /opt/ats/app
sudo -u ats git pull origin arena/01a072c1-ats   # новая версия
sudo systemctl restart ats
```

Данные не затрагиваются (они в `/var/lib/ats`, код в `/opt/ats/app`).
Перед обновлением можно вручную сделать бэкап: `sudo -u ats ... --init-only`
не нужен — достаточно скопировать `/var/lib/ats/ats.db`.

## 10. Полезные операции

| Задача | Команда |
|---|---|
| Логи | `journalctl -u ats -f` |
| Статус | `systemctl status ats` |
| Перезапуск | `systemctl restart ats` |
| Сменить пароль админа | `sudo -u ats env ATS_DATA_DIR=/var/lib/ats /opt/ats/app/venv/bin/python -m app.run --admin-password 'Новый' --init-only` |
| Убрать демо-записи (если переносили старую базу) | та же команда с `--clean-demo` |
| Откат базы из бэкапа | остановить службу, заменить `/var/lib/ats/ats.db` файлом из `backups/`, запустить |

## 11. Частые проблемы

| Симптом | Причина / решение |
|---|---|
| Сайт не открывается | nginx не запущен / DNS не указал на сервер: `nginx -t`, `systemctl reload nginx`, `dig ats.example.com` |
| `Address already in use` в логах | порт 9124 занят: `ss -ltnp | grep 9124` |
| Зелёный индикатор SSE мигает/нет связи | буферизация nginx для `/api/v2/events` (см. п.5.1, `proxy_buffering off`) |
| Не грузится запись разговора | `client_max_body_size` в nginx (см. п.5.1) |
| Нет браузерных уведомлений у операторов | сайт должен открываться по HTTPS (см. п.5.2) |
| Не приходят вебхуки UIS | вебхук должен быть по HTTPS и доступен из интернета: `curl -I https://ats.example.com/api/v2/webhooks/uis` |
| Расписание звонков «не в то время» | часовой пояс сервера: `timedatectl` (см. п.1) |

## 12. Вариант: Windows Server

Тот же порядок, но служба ставится через **NSSM**:

```bat
cd C:\ATS
python -m venv venv
venv\Scripts\activate
:: первый запуск (создаст базу и админа)
set ATS_DATA_DIR=C:\ATSData
set ATS_ADMIN_PASSWORD=СложныйПароль123!
python -m app.run --init-only

:: регистрация службы
nssm install ATS "C:\ATS\venv\Scripts\python.exe" "-m app.run --host 127.0.0.1 --port 9124"
nssm set ATS AppDirectory C:\ATS
nssm set ATS AppEnvironmentExtra ATS_DATA_DIR=C:\ATSData
nssm start ATS
```

Данные — в `C:\ATSData` (вне папки кода). HTTPS/nginx — как в п.5, либо IIS
с reverse-proxy (ARR) / Caddy для Windows.
