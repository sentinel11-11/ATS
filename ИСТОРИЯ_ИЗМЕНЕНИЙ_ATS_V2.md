# ATS v2 — что сделано в проекте (история изменений)

**ATS v2** — платформа исходящего обзвона (call-центр): кампании с расписанием и
автодозвоном, пул номеров Caller ID с защитой от антиспама, ИИ-агент для
квалификации звонков, перевод на оператора (ACD), журнал и отчёты, записи
разговоров, интеграции с телефонией (UIS / Asterisk AMI / симулятор) и CRM
(CSV / Bitrix24). Всё в одном процессе, без внешних зависимостей (SQLite,
стандартная библиотека Python), одиночный HTML-файл интерфейса.

Ветка разработки: `arena/01a072c1-ats` (Pull Request №1 в GitHub).
Ниже — изменения по коммитам, от старого ядра к текущему интерфейсу.

---

## 1. Платформа исходящего обзвона — ядро, API, UI, телефония/CRM, тесты
**Коммит `2799c3d`**

- **Движок обзвона** (`app/engine.py`): очередь кампаний, окно звонков и дни
  недели, попытки дозвона и базовые интервалы повторов, суточные лимиты и
  «остывание» номеров, автокарантин номера при жалобах, ACD-очередь на
  оператора, «зависшие» звонки (watchdog).
- **ИИ-агент**: квалификация абонентов по сценарию (вопросы/ответы 1/2),
  перевод «квалифицированных» на оператора, отказ при отсутствии согласия,
  чёрный список «не звонить».
- **Телефония** (`app/telephony.py`): симулятор без оборудования + UIS
  (МегаФон «Ювис» Call API). **CRM**: выгрузка CSV + вебхук Bitrix24.
- **REST API v2** (`app/api.py`): авторизация с токеном, роли admin/operator,
  контакты/номера/кампании/шаблоны/операторы/журнал/чёрный список/настройки,
  события в реальном времени (SSE), вебхук UIS.
- **UI v2** (`app/ui/index.html`): одиночная страница со всеми разделами.
- Перенос legacy-данных (контакты/шаблоны старой версии), тесты.

## 2. AMI-клиент Asterisk, UIS-вебхук, ACD-timeout, документация
**Коммит `dfa623a`**

- Клиент Asterisk AMI (`app/asterisk.py`) — реальный SIP-провайдер для
  клиентской АТС (originate/состояния/завершение), «проверка соединения».
- UIS: приём webhook-событий от Call API и перевод их в события движка.
- ACD: таймаут ожидания оператора → результат `no_operator` + задача на
  перезвон.
- Настройки `uis/ami/llm/bitrix24` в конфигурации, единый REST под RAW-конфиг.
- Документация: `README_V2.md`, `ПЛАН_ДОРАБОТКИ_ATS.md`, `ДОРОЖНАЯ_КАРТА_ATS.md`,
  скрипты запуска `run_ats2.bat/.sh`, расширенные тесты.

## 3. Отчёты, защита входа от перебора, экспорт журнала, UX
**Коммит `003f68f`**

- **Отчёты**: за сегодня, по кампаниям, по Caller ID, динамика 7 дней;
  карточки-метрики в UI.
- **Защита от перебора пароля**: задержки/блокировка после неудачных входов
  (429 + `retry_after_sec`).
- **Экспорт журнала** звонков в CSV; фильтр журнала по результату.
- Интерфейс: статусы звонков бейджами, кнопки действий в таблицах, авто-бэкап
  базы при старте сервера.

## 4. Записи разговоров, умный автодозвон, демо-данные, авто-бэкап БД
**Коммит `9e55aca`**

- **Записи разговоров**: загрузка файла по звонку (админ), прослушивание из
  UI, папка `data_v2/recordings/`.
- **Умный автодозвон**: `retry_map` кампании — индивидуальные паузы повтора по
  причинам (занято → 5 мин, нет ответа → 20 мин и т.п.), редактор в форме
  кампании.
- **Демо-данные** одной кнопкой: контакты + «Демо-кампания (ИИ-агент)».
- **Авто-бэкап БД** при каждом старте: `data_v2/backups/ats-ГГГГММДД-ЧЧММСС.db`,
  хранение последних 12 копий.
- Загрузка записи разговора и демо-режим покрыты тестами.

## 5. Ровная адаптивная вёрстка без «дёрганий»
**Коммит `ead9151`**

- Единые отступы/типографика: сетки форм (`.formgrid`), компактные кнопки,
  липкий сайдбар, адаптив под узкие экраны.
- «Настройки»: двухколоночная форма, расписание звонков со временем и чипами
  дней недели; панели RAW-конфига и смены пароля — только у администратора.
- **Анти-jank**: дебаунс обновлений по SSE, локальный фильтр контактов без
  лишних запросов, защита от гонок при переключении вкладок, плавные модалки.

## 6. Современный интерфейс: палитра, тосты, живые панели, диаграммы, роли
**Коммит `0dccfdb`**

- **Дизайн**: «стеклянные» панели с блюром, градиенты, иконки, аватары,
  аккуратные тосты вместо `alert/confirm`.
- **Экран входа** на весь экран; интерфейс **подстраивается под роль**:
  оператор видит приём звонков/статусы/базу, админ — всё управление
  (недоступные кнопки скрыты).
- **Быстрый доступ**: `Ctrl+K` — палитра переходов (разделы, кампании,
  контакты), `F5` — обновление раздела, индикатор live-подключения.
- **Обзор**: метрики с иконками, пул номеров с прогресс-барами лимита дня,
  лента последних звонков.
- **Кампании**: детальная карточка с метриками, переключатель
  «Контакты / Звонки», запуск/пауза/остановка, загрузка записей.
- **ACD**: карточки очереди и операторов; при приёме — панель «Активный
  разговор» с кнопкой завершения; статусы «Свободен/Перерыв» в шапке.
- **Отчёты**: диаграммы результатов/кампаний/номеров + 7-дневный тренд.
- **Журнал**: человеческие названия результатов, длительность разговора,
  кнопка «Показать ещё».
- **Контакты**: выбор строк кликом + панель массовых действий
  («Добавить в кампанию», «Удалить»).
- **Исправлено**: `/acd/accept` возвращает `operator_id`, поэтому после
  «Завершить разговор» оператор корректно освобождается (раньше «залипал»).

## 7. Управление операторами, отчёты за период, уведомления о звонках, честный импорт
**Коммит `69d8ea7`** (батч «Всё по порядку, без вопросов»)

- **Пользователи и операторы** (Настройки → только админ): список с ролями,
  статусами «на линии» и переключателем доступа; создание/редактирование
  (логин, роль, имя оператора, внутренний номер, пароль); отключение доступа
  мгновенно выводит пользователя из системы (сброс сессий); удаление. Защита:
  нельзя отключить/понизить/удалить самого себя и последнего администратора.
  `need_auth` теперь сверяет `active=1` и актуальную роль с БД на каждом
  запросе.
- **Смена пароля** доступна и оператору (свой пароль, мин. 6 символов); сброс
  пароля администратором завершает чужие сессии пользователя.
- **Звук и браузерные уведомления**: кнопка-колокольчик в шапке; новый звонок
  в ACD-очереди (`type=acd, status=queued`) — двухтоновый гудок (WebAudio) +
  системное уведомление (Notification API) с именем/телефоном абонента,
  защита от дублей и устаревших событий.
- **Отчёты за произвольный период**: пресеты «Сегодня / 7 / 14 / 30 дней» и
  выбор дат «с — по» (до 366 дней); бэкенд `_reports(from, to)` отдаёт метрики,
  разрезы и динамику (по дням до 31 точки, дальше — по неделям); заголовки и
  подписи учитывают выбранный период.
- **Импорт CSV — отчётность вместо тихого пропуска**: ответ
  `added/updated/skipped` + первые 50 ошибок с причинами («нет телефона»,
  «не похоже на телефон (10–15 цифр)», «дубль в файле»); в UI — счётчик
  пропущенных и список причин по строкам. Валидация телефона E.164 (10–15
  цифр) распространяется и на ручное сохранение контакта.
- **Исправлено**: сохранение контакта из UI шло на `/contacts/save`, которого
  не было в API — маршрут добавлен (и для оператора).

## 8. Чистый продукт: демо-данные удалены
**Коммит `xxxxxxxx`** (решение «убрать демо для итогового продукта»)

- **Первый запуск больше не создаёт** оператора-демо (`operator/operator1234`)
  и номера-заглушки «Пилотный №1…5». Чистый старт: один администратор,
  пустая база контактов, пустой пул номеров. Операторов заводит администратор
  (Настройки → Пользователи и операторы), номера добавляются в «Пул номеров» —
  тот же путь, что и для реальных номеров UIS.
- **Кнопка «Загрузить демо-данные» и API `POST /api/v2/demo/seed` удалены**
  (отвечают 404). В разработке/тестах пул sim-номеров наполняется флагом
  `ATS_DEV_SEED=1` (движку и E2E-тестам нужен Caller ID в симуляторе).
- **Legacy-импорт** из папки `data/` (v1-прототип) срабатывает только при
  реальной миграции: в legacy-файле есть контакты. Пустой legacy больше не
  добавляет «лишние» шаблоны в свежую продуктивную базу.
- **Очистка уже созданных демо-записей**: `python -m app.run --clean-demo` —
  удаляет сид-контакты (`consent_source='demo'`), «Демо-кампанию…», оператора
  `operator`/«Оператор (демо)» и связанные элементы/звонки/очередь; обычные
  контакты/кампании/операторы не затрагиваются. Перед очисткой — авто-бэкап БД.
- Провайдер **sim остаётся** как режим приёмки без оборудования (панель
  задания исхода звонка на «Обзоре»); в интерфейсе переименован в
  «sim · тест без оборудования» и не рекламирует демо.
- Тесты: **29/29** (вместо проверок demo-seed — проверки чистой инициализации,
  отсутствия роута `/demo/seed` и корректной работы `clean_demo()`).

## 9. Базы данных для обзвона: загрузка Excel/CSV, теги, карточка номера
*(этот коммит — следующий за `df1518f`, см. git log)*

- **Загрузка базы файлом**: кнопка «Загрузить базу» в разделе «Контакты» —
  файл `.xlsx` или `.csv` (до ~48 МБ) разбирается на сервере без внешних
  библиотек (XLSX — через zip+XML стандартной библиотеки).
- **Авто-распознавание**: кодировка (utf-8/cp1251) и разделитель CSV (`; , \t |`)
  определяются сами; колонки «Телефон / Phone», «Имя / Name», «Группа»,
  «Теги», «Примечание», «Согласие» находятся по русским/английским заголовкам;
  понимается и простой список номеров без заголовков.
- **Нормализация номеров**: `8(929)…`, `+7…`, `929…` приводятся к `7XXXXXXXXXX`;
  по каждой пропущенной строке — причина с номером строки файла.
- **Базы данных** (`databases`): каждая загрузка создаёт именованную базу
  (или догружает в выбранную); у базы — счётчики контактов/согласий и сводные
  теги; удаление — с откреплением контактов или вместе с ними.
- **Теги номеров**: из колонки файла (объединяются при повторной загрузке)
  + ручные; поиск и отображение чипами; фильтр в кампанию по тегам.
- **Карточка номера**: клик по имени — контакт + динамика (звонки с результатами
  и длительностями, участие в кампаниях, попытки) в виде таймлайна.
- **Кампания из базы целиком**: в окне добавления контактов — выбор базы
  («Добавить базу целиком»); API `add-contacts` принимает `database_id` и `tags`.
- Миграция старых БД: колонки `contacts.database_id`/`tags` добавляются
  автоматически (`ALTER TABLE`); экспорт контактов дополнен базой и тегами.
- Тесты: **43/43** (новый `tests/test_import_db.py`: нормализация, парсеры
  CSV/XLSX, API импорта/баз/истории, роли, удаление).

## 10. Production Hardening по внешнему аудиту
*(этот коммит — следующий за `e2b9196`, см. git log)*

По итогам независимого технического аудита ветки закрыт пакет hardening
(без изменения архитектуры — ядро/БД/UI/кампании не трогались):

- **Пул номеров**: `TODAY` больше не кэшируется на момент импорта модуля —
  суточные лимиты корректно сбрасываются после полуночи (`numbers.today()`).
- **Static-файлы**: убрано мёртвое условие `if rel != rel`, path traversal
  проверяется через `Path.relative_to()` (выход за `STATIC_DIR` невозможен).
- **Тихий fallback на sim запрещён**: если настроенный провайдер (uis/ami)
  недоступен, сервер громко не стартует. Обход для стенда — только явно:
  `ATS_ALLOW_SIM_FALLBACK=1`.
- **Вебхук UIS**: без настроенного `webhook_secret` отвечает 403
  `webhook_disabled`; с секретом требует заголовок `X-UIS-Secret`.
- **Секреты в API**: `GET /settings/raw` маскирует ключи (`********`),
  POST сохраняет старые значения по плейсхолдеру; имя env-переменной
  (`api_key_env`) секретом не считается. В UI добавлена подсказка.
- **Стартовые учётки**: `initial_credentials.txt` создаётся с правами 600
  и автоматически удаляется при смене пароля админа (UI и CLI).
- **ACD**: убрана фабрикация «виртуальных операторов» (и в `accept_acd`,
  и в API-принятии); бридж провайдера вызывается ДО простановки
  `operator_ok`, при ошибке — откат в очередь + `transfer_failed`.
- **Агент**: при отсутствии интерактивного канала у провайдера — честный
  результат `engine=no_channel` вместо падения на `None`.
- Тесты: **54/54** (новый `tests/test_hardening.py`: 11 проверок).
- Починены счётчики тестов в документации (были устаревшие 22 и 12).

Сознательно отложено до интеграции с провайдером (нужны реальные доки/стенд):
голосовой медиаслой (TTS/ASR), проверка бриджа на живой АТС, Bitrix-mapping,
reputation-события номеров, воркеры движка, Windows EXE для v2.

Windows (PowerShell, из папки проекта, в виртуальном окружении):

```powershell
cd "C:\Users\ilaci\OneDrive\Рабочий стол\ATS"
python -m app.run
```

или двойным кликом/командой: `.\run_ats2.bat`

После старта откройте **http://localhost:9124**

- Порт и хост по умолчанию: `0.0.0.0:9124` (доступен в локальной сети).

  (удаляет только демо-контент; перед очисткой делается авто-бэкап БД).

  разделе «Настройки → Провайдеры и интеграции» (только админ).
