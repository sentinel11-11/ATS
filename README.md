# ATS — система автоматического обзвона (исходящие кампании)

Проект развивался в две итерации:

- **`README_RU.txt` + `server.py`, `xp_bridge/`, `static/`** — исходный прототип «диспетчер очереди на GSM-модемах» (legacy, не используется новой версией).
- **`app/` (ATS v2)** — переработанная платформа исходящего обзвона под требования заказчика: кампании («карусель»), автодозвон, пул номеров с ротацией Caller ID, согласия/чёрный список, ИИ-агент, перевод на сотрудника (ACD), телефония и CRM за интерфейсами-адаптерами, SQLite, REST API v2, веб-UI, тесты.

## Быстрый старт (v2)

```bash
./run_ats2.sh                      # Linux/macOS (данные в ./data_v2)
# Windows: run_ats2.bat
# ATS_ADMIN_PASSWORD='...' python3 -m app.run --host 0.0.0.0 --port 9124
```

При первом запуске создаются `data_v2/ats.db` и файл `data_v2/initial_credentials.txt` с паролем администратора (роль admin). Операторов добавляет администратор: Настройки → Пользователи и операторы. Пул номеров и база стартуют пустыми — номера и контакты добавляются в интерфейсе. Интерфейс: `http://127.0.0.1:9124`.

Тесты: `python3 -m unittest discover -s tests -v` (29 проверок: ядро, пул, E2E, HTTP API, AMI-протокол, вебхуки UIS, ACD). В тестах пул sim-номеров наполняется автоматически (`ATS_DEV_SEED=1`), в продукте — пуст.

## Документация

- `README_V2.md` — устройство кода v2, REST API, статусы звонков, подключение реальной телефонии (UIS/Asterisk).
- `ПЛАН_ДОРАБОТКИ_ATS.md` — требования заказчика, целевая архитектура, этапность (редакция 3).
- `ДОРОЖНАЯ_КАРТА_ATS.md` — исполняемый список задач T01–T42 со статусами (Приложение C).
- `АНАЛИЗ_ПРОЕКТА_ATS.md` — разбор исходного прототипа.

## Что осталось «вне кода» (внешние зависимости)

Ответ UIS (SIP/Call API) → транспорт в `app/telephony.py`; настройка Asterisk и проверка AMI-адаптера на живом стенде; юрист (согласия 152-ФЗ); ответы клиента (CRM, сценарий бота); договоры с операторами; пилотные кампании на реальных номерах.
