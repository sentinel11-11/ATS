# Административный аудит ATS

## Назначение

`audit_logs` — отдельный журнал действий пользователей и интеграционных ошибок. Он не заменяет журнал звонков (`calls`) и не хранит аудио, пароли, токены, ключи провайдеров или полный импорт контактов.

Запись выполняется best effort: сбой аудита не блокирует исходную операцию. Для запросов через HTTP сохраняются пользователь, роль, время, endpoint, IP (из reverse proxy или socket), категория, действие, объект, результат и безопасное краткое описание запроса/ответа.

## Хранение

SQLite-таблица `audit_logs` находится в той же БД `/var/lib/ats/ats.db` и входит в обычный WAL-safe backup. Индексы покрывают время, категорию/действие, пользователя и объект:

- `created`
- `event_type, action`
- `actor_user_id, actor_login`
- `entity_type, entity_id`

Секретные поля редактируются до сериализации (`password`, `token`, `api_key`, `secret`, `authorization` и варианты названий). Большие payloads ограничиваются по размеру. Политика retention должна задаваться отдельно после согласования срока хранения; до этого записи не удаляются автоматически.

## API

Только администратор:

```text
GET /api/v2/audit/logs
```

Параметры фильтрации:

- `from`, `to` — дата или timestamp;
- `event` — `auth`, `settings`, `campaign`, `contact`, `blacklist`, `operator`, `integration`, `export`;
- `action` — например `login`, `save`, `delete`, `start`, `status`, `accept`;
- `status` — `success` или `failure`;
- `actor` — login или user id;
- `q` — поиск по пользователю, действию, объекту, коду ошибки и endpoint;
- `limit` (1–500), `offset`.

Ответ содержит `logs`, `total`, `limit`, `offset`. `details` уже возвращается как JSON-объект и может быть раскрыт в UI.

## Категории событий

- авторизация: успешный/неуспешный login, блокировка перебора, logout;
- настройки и пользователи;
- кампании, шаблоны, запуск/остановка и очереди;
- контакты и базы;
- чёрный список и жалобы;
- статус оператора, ACD, завершение звонка;
- интеграции, вебхуки и ошибки проверки провайдера;
- экспорт данных.

Админская страница доступна в меню **Админские логи**, поддерживает фильтры, пагинацию и раскрытие безопасных деталей. При production-развёртывании проверяется наличие таблицы миграцией `db.init_db()` и до обновления сохраняется backup каталога `/var/lib/ats`.
