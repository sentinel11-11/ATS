# Интеграция ATS ↔ amoCRM (REST API v4)

Документ описывает актуальную (после аудита и исправлений) интеграцию исходящего
обзвона ATS с amoCRM: что и куда пишется, как настраивается, какие коды
статусов используются и что осознанно оставлено за рамками.

## 0. Что увидит менеджер в amoCRM (коротко, для людей)

После завершённого звонка АТС в amoCRM появляется:

| Где | Что |
|---|---|
| Карточка контакта → «История»/таймлайн | Системное событие «Звонок» с иконкой телефона: длительность, статус (`call_status`), результат, запись разговора (ссылка `link`), время звонка |
| Контакт → примечание | Текст: результат, длительность, итог ИИ-диалога (что ответил клиент) |
| Задача «Перезвонить» | Создаётся только по неуспешным результатам (занято/нет ответа/автоответчик/не дождался оператора), срок — по умолчанию «через 4 часа» |
| Ответственный | Реальный сотрудник: по карте `operator_user_map`, иначе — ответственный контакта, иначе — `responsible_user_id` интеграции |
| Аналитика «Все звонки» | Статистика по статусам/источнику `Axioma ATS`, отчёты amoCRM по звонкам работают «из коробки» |

Ничего настраивать в amoCRM для этого не нужно, кроме прав интеграции (приватная
интеграция с доступом к «Телефония», «Контакты», «Задачи», «Заметки»).

## 1. Архитектура

```
ATS Engine ──► CrmDriver (AmoCrm) ──► AmoCrmClient ──► amoCRM /api/v4
     │                │                     │
     │                │                     ├─ rate limiter (≤7 rps, квота amoCRM)
     │                │                     ├─ 429 → Retry-After/backoff
     │                │                     └─ 401 → OAuth refresh (если настроен) → retry
     │                │
     │                └─ push_result(call): поиск/создание контакта →
     │                   POST /calls (uniq, call_status, link) →
     │                   задача (только неуспех) → примечание (аналитика)
     │
     └─ при сбое ──► crm_outbox (SQLite) ──► повторы тиками движка
                     с экспоненциальным backoff до 8 попыток
```

Разделение ответственности: `Engine` не знает HTTP-контракта amoCRM;
`AmoCrm` — бизнес-правила (маппинг, задачи); `AmoCrmClient` — транспорт
(авторизация, квоты, OAuth).

## 2. Что пишется в amoCRM при завершении звонка

1. **Контакт** (`GET/POST /contacts`) — поиск по номеру с ТОЧНОЙ сверкой
   последних 10 цифр (amoCRM ищет нечётко); при отсутствии — создание
   (`auto_create_contacts`). Ошибки поиска (401/429/5xx) НЕ трактуются как
   «контакта нет» — push прерывается и уходит в outbox, дублей не создаётся.
2. **Звонок** (`POST /calls`) — официальный контракт телефонии:
   `uniq=ats-call-<id>` (идемпотентность), `direction`, `duration`,
   `call_status` (см. таблицу), `call_result` (текст результата),
   `responsible_user_id`, `call_responsible` (имя из `provider.user` ВАТС,
   если есть), `link` (запись из `calls.recording_url`), `created_at`
   (время начала звонка).
3. **Задача** (`POST /tasks`) — ТОЛЬКО для неуспешных результатов
   (настраивается `auto_task_results`); `task_type_id` из настроек.
4. **Примечание** (`POST /contacts/{id}/notes`, тип `common`) — детали
   звонка и итог ИИ-диалога. Системный телефонный факт живёт в `/calls`,
   заметка — только для текста/аналитики.

## 3. Маппинг результатов ATS → `call_status` amoCRM

Официальная семантика amoCRM: 1 — оставил сообщение, 2 — перезвонить позже,
3 — нет на месте, 4 — разговор состоялся, 5 — неверный номер,
6 — не дозвонился, 7 — номер занят.

| result ATS (calls.result)                              | call_status |
|--------------------------------------------------------|-------------|
| `done_ok`, `operator_ok`, `done_agent`                 | 4 — разговор состоялся |
| `busy`                                                  | 7 — номер занят |
| `no_answer`, `timeout`, `missed`, `machine`, `no_media`, `failed`, `canceled`, `exhausted` | 6 — не дозвонился |
| `wrong_number`, `invalid_number`                        | 5 — неверный номер |
| `no_operator`, `rejected`, `declined`                   | 2 — перезвонить позже |
| `blocked*`, `blacklisted`, `dialing`, пусто             | в amoCRM не отправляется |

Важно: маппинг строится по **calls.result**, а не по calls.status
(у завершённого звонка status всегда `'done'`). Переопределение —
`amocrm.call_status_map = {"machine": 1}` и т.п.

## 4. Настройки (`Настройки → CRM` или /settings/raw, секция `amocrm`)

| Поле | Назначение |
|---|---|
| `subdomain` | субдомен аккаунта (`company` из company.amocrm.ru) |
| `access_token` / `access_token_env` | долгосрочный токен (вкладка «Ключи» приватной интеграции) |
| `client_id`, `client_secret`, `refresh_token`, `redirect_uri` | OAuth-режим: по 401 клиент обновляет пару токенов и АТОМАРНО сохраняет новую (refresh одноразовый) |
| `responsible_user_id` | ответственный по умолчанию для контактов/звонков/задач |
| `operator_user_map` | карта `{"vats_login/ext": amo_user_id}` — звонок/задача вешаются на реального сотрудника |
| `use_contact_responsible` | брать ответственного из найденного контакта (true по умолчанию) |
| `auto_create_contacts` / `auto_create_tasks` | автосоздание контактов / задач «перезвонить» |
| `auto_task_results` | список результатов, для которых создаётся задача |
| `task_type_id` | id типа задачи (справочник: `GET /account?with=task_types`) |
| `call_status_map` | переопределение маппинга результатов |
| `webhook_token` / `webhook_token_env` | секрет вебхука amoCRM (fail-closed: без него вебхук выключен) |
| `rate_limit_rps` | локальный лимит запросов (≤7/с — квота amoCRM) |
| `timeout_sec` | HTTP-таймаут |

Секреты можно хранить в переменных окружения (поля `*_env`), в БД значения
маскируются в UI.

Сложные типы (`operator_user_map`, `call_status_map`, `auto_task_results`,
булевы флаги) хранятся в настройках как есть — `POST /settings/raw` больше
не делает `str()` для всех значений (иначе `"False"` truthy в Python и снятие
галочки «автосоздание контакта/задачи» не работало, а dict превращался в
строку). Драйвер дополнительно толерантен к legacy-строкам (`_amo_flag`:
`"false"/"0"/"нет"/"no"/"off"/""` → `False`).

### Редактор соответствий операторов (UI)

В карточке amoCRM (`Настройки → CRM`, драйвер `amocrm`) после поля «ID
Ответственного пользователя» — блок «Соответствие операторов ATS →
пользователей amoCRM» для поля `operator_user_map`:

- список пользователей amoCRM подтягивается из `GET /api/v2/amocrm/users`
  (снимок таблицы `amo_users`; если пуст — подсказка «сначала
  синхронизируйте пользователей»);
- ключ оператора ATS = `op_vats || ext || login` (уже привязанные скрываются
  из select'а);
- добавление/удаление правит `operator_user_map` в памяти, сохранение —
  общей кнопкой «Сохранить все настройки» (`POST /settings/raw`).

## 5. Вебхук `POST/GET /api/v2/amocrm/webhook`

- Внешний (без X-ATS-Token), защищён секретами:
  - **POST** (события/клик из виджета): `?token=<webhook_token>` или заголовок
    `X-Amo-Token`. Click-to-call в движке пока не реализован — ответ `501
    click2call_not_supported` (явно, без падений).
  - **GET** (хук отключения интеграции): `client_uuid`, `account_id`,
    `signature`; подпись проверяется как `HMAC-SHA256(client_uuid+account_id,
    client_secret)` по официальной схеме amoCRM. При валидной подписи
    интеграция выключается (`amocrm.disabled=true`, драйвер fail-closed).
- Без `webhook_token` / `client_secret` маршрут выключен (`403 webhook_disabled`).

## 6. Синхронизация менеджеров и правило «401 не проксируем»

`POST /api/v2/amocrm/users-sync` (admin) забирает `GET /users` и СОХРАНЯЕТ
снимок в таблицу `amo_users` (раньше возвращался JSON без сохранения).
Ошибки amoCRM (401/403/429/5xx) теперь пробрасываются как сбой синхронизации,
а не как «пользователей 0».

`GET /api/v2/amocrm/users` (admin) отдаёт этот снимок
`{ok: true, users: [{id, name, email, ...}]}` для UI-редактора соответствий
(см. раздел 4). Без ATS-сессии — `401 auth_required`, как у всех
приватных роутов.

Правило «401 не проксируем»: наружный HTTP 401 означает ТОЛЬКО истёкшую
ATS-сессию (`need_auth`). Ошибки upstream-провайдеров — в т.ч. 401 от amoCRM
(неверный/протухший токен) в `_amocrm_check_route` и `_amocrm_users_sync_route` —
всегда отдаются как HTTP 502, а код amoCRM кладётся в поле `http_status`
payload'а. Причина: `frontend/src/api.js` при любом HTTP 401 сбрасывает сессию
и показывает окно логина — проксирование upstream-401 выкидывало админа из
сессии при нажатии «Проверить связь».

## 7. Надёжность доставки: `crm_outbox`

При любой ошибке `push_result` (amoCRM недоступна, 401/429/5xx, сеть)
снапшот звонка кладётся в `crm_outbox`; движок повторяет доставку каждый тик
(пачками до 5), backoff `2^attempts` минут (потолок 2ч), после 8 попыток —
`failed`. `uniq` делает повтор безопасным: дубль звонка в amoCRM не создаётся.

## 8. Unsorted («Неразобранное»)

`create_unsorted()` — только для ВХОДЯЩИХ звонков (так задуман SIP-режим
amoCRM): снабжён обязательным `metadata` (номер, время, длительность,
ссылка на запись) и `source_uid=uuid4`. Исходящий обзвон в неразобранное
не кладётся — регистрируется через `/api/v4/calls`.

## 9. Сознательно не реализовано (дорожная карта amoCRM Integration v2)

- Полный OAuth-рконнект из UI (кнопка «Подключить amoCRM», redirect flow,
  хранение `oauth_states`): сейчас OAuth поддержан на уровне refresh-ротации.
  Рекомендуемый прод-режим — долгосрочный токен приватной интеграции
  (1 день — 5 лет, без refresh).
- Воронки/этапы (`/leads/pipelines`), создание сделок `/leads`, таблица
  связей `crm_links` (ATS entity ↔ amo entity) — нужны для сценария
  «кампания → сделка в воронке».
- Подписанные URL записей разговоров (локальные записи отдаются только по
  авторизованному API; в `link` уходит провайдерская `recording_url` ВАТС).
- Click-to-call из виджета amoCRM (возвращается явный 501).
- Мультиаккаунт amoCRM (сейчас один аккаунт на инстанс ATS), платформа
  amocrm.com/kommo.com (хост зашит `*.amocrm.ru`).
- Пакетное создание контактов (batch) при массовом импорте.

## 10. Пошаговое подключение (15 минут, руками администратора)

1. **amoCRM → Настройки → Интеграции → «Добавить» → Приватная интеграция.**
   - Название: `Axioma ATS`; «Домен»: ваш субдомен; «Пользователи»: все, от имени кого
     пишутся звонки; «Срок действия»: максимум (тогда токен не нужно обновлять);
   - Права: `CRM` (чтение/запись контактов, задач, заметок) и `Телефония`
     (запись звонков). Скопируйте ** Секретный ключ** со вкладки «Ключи».
2. **АТС → Настройки → «CRM и интеграции»:**
   - «CRM-драйвер»: `amoCRM — REST API v4`;
   - «Субдомен»: `company` (из `company.amocrm.ru`), без `https://` и `/api/v4`;
   - «Токен доступа»: вставленный секретный ключ (не `********`!);
   - «ID ответственного»: id менеджера по умолчанию (из `GET /api/v4/users` или из URL
     профиля пользователя amoCRM);
   - нажмите **«Проверить связь»** — должно показать имя и id аккаунта.
3. **Соответствие операторов:** «Синхронизировать менеджеров» (заполнит `amo_users`),
   затем в блоке «Соответствие операторов ATS → пользователей amoCRM» добавьте пары
   `логин/внутренний номер ↔ amo_user_id`. Без карты все звонки будут висеть на
   «ответственном по умолчанию».
4. **Флаги:** «Автосоздание контакта» (нужно, если база АТС шире CRM),
   «Автосоздание задач» + `auto_task_results` (какие результаты порождают «перезвонить»),
   `task_type_id` (если в аккаунте не дефолтный тип задачи).
5. **«Сохранить все настройки»** — АТС сразу перезагрузит драйвер (`Engine.reload_settings`).
6. **Тест:** заведите контакт с реальным номером, запустите тестовую кампанию
   (`flow=operator`), дождитесь финала. Проверьте: карточка контакта → звонок с
   правильным `call_status`, примечание, (если результат неуспешный) задача.
7. **Воронка/сделки** — если нужно создавать лиды по итогам обзвона, это отдельная
   дорожная карта (§9), а не часть текущей интеграции.

## 11. Диагностика: симптом → где смотреть → что делать

| Симптом | Причина | Как проверить / починить |
|---|---|---|
| «Проверить связь» → `502 amocrm_error`, в `http_status` 401 | Токен неверный/отозван/истёк, либо не тот субдомен | Взять новый ключ из приватной интеграции; проверить субдомен; для OAuth-режима — `client_id/secret/refresh_token` (клиент сам обновит пару при 401) |
| Выбрасывает из АТС на экран логина после «Проверить связь» | Так быть не может: наружный 401 = только истёкшая сессия ATS; ошибки amoCRM отдаются 502 (§6) | Обновить АТС до ревизии с фиксом (`deploy/update.sh`) |
| Звонков в amoCRM нет, в журнале АТС есть | Драйвер не `amocrm`; либо результат входит в «не отправлять» (`blocked*`, `blacklisted`, `dialing`) | `GET /api/v2/settings/raw` → `crm.driver`, `amocrm.disabled`; проверить `calls.result` |
| Звонков нет, а ошибки CRM в логе | Сбой доставки: записи скопились в `crm_outbox` | `sqlite3 data_v2/ats.db "SELECT id,status,attempts,last_error,updated FROM crm_outbox ORDER BY id DESC LIMIT 20"`; чинить доступность amoCRM/токен — отправка продолжится сама |
| Дубли контактов | В amoCRM уже несколько контактов с одинаковым хвостом номера | В логе: `[amocrm] дубль контакта по номеру …`. Зачистить дубли в amoCRM (АТС берёт первый и не плодит новых) |
| Звонки «приписаны» не тому менеджеру | `operator_user_map` не заполнена / ключ не совпал | Ключ = `vats_login` → `ext` → `login` (первое непустое). Проверить синк менеджеров и карту |
| Нет записи разговора в карточке | АТС кладёт в `link` провайдерский `recording_url`; записей на стороне оператора нет | Настроить запись у оператора/ВАТС, либо загружать файл в АТС (`POST /api/v2/calls/recording`) и отдавать ссылку вручную |
| Задача «перезвонить» не создаётся | Результат не входит в `auto_task_results`, либо `auto_create_tasks=false`, либо нет `task_type_id` | Проверить настройки и `calls.result`; `task_type_id` взять из `GET /api/v4/account?with=task_types` |
| Снял(а) галочку «автосоздание контакта», а оно всё равно работает | Старые БД могли хранить строку `"False"` (truthy) | Уже лечится `_amo_flag` (ложь = `false/0/нет/no/off/""`); пересохранить настройки |
| amoCRM отключила интеграцию | Сработал хук отключения (GET-вебхук с подписью) → `amocrm.disabled=true` | Включить обратно в amoCRM и снять флаг в `amocrm` (§5) |
| В «Неразобранное» нет исходящих | Так задумано: unsorted — только для входящих (§8) | Исходящий обзвон живёт в «Все звонки» |

Полезные one-liner'ы:

```bash
# что именно ушло (и что застряло) в CRM
sqlite3 data_v2/ats.db "SELECT id,kind,status,attempts,substr(last_error,1,120) FROM crm_outbox ORDER BY id DESC LIMIT 20"
# финальные результаты последних звонков — по ним считается call_status
sqlite3 data_v2/ats.db "SELECT id,contact_phone,status,result,duration_sec,substr(detail,1,60) FROM calls ORDER BY id DESC LIMIT 15"
# живой health: драйвер CRM, настройки (маскированные)
curl -s -H "X-Ats-Token: $T" localhost:9124/api/v2/health/details | jq '.provider_config.crm, .provider_config.amocrm | {driver,subdomain,rate_limit_rps,auto_create_contacts,auto_create_tasks}'
```

## 12. Чек-лист приёмки после настройки или обновления

- [ ] `POST /api/v2/amocrm/check` → `ok: true`, имя аккаунта верное;
- [ ] `POST /api/v2/amocrm/users-sync` → `count > 0`, в `amo_users` есть нужные менеджеры;
- [ ] в `operator_user_map` есть пары для всех операторов, которые принимают звонки;
- [ ] тестовый **дозвон с разговором** → в amoCRM: событие «Звонок» со статусом
      «Разговор состоялся» (`4`), примечание, правильный ответственный, **нет** задачи;
- [ ] тестовый **недозвон** (`no_answer`) → статус «Не дозвонился» (`6`) + задача
      «Перезвонить клиенту» на нужном менеджере;
- [ ] повторный пуш того же звонка (перезапуск АТС «в момент пуша») → **дублей нет**
      (работает `uniq = ats-call-<id>`);
- [ ] `crm_outbox` пуст (или все записи `done`);
- [ ] запись разговора открывается из карточки, если оператор её отдаёт.

## 13. Частые вопросы

- **«Почему 7 запросов в секунду?»** — квота amoCRM на интеграцию; локальный лимитер
  (`rate_limit_rps`) не даёт в неё упираться, 429 отрабатывается backoff'ом.
- **«Можно несколько аккаунтов amoCRM?»** — нет: один инстанс АТС = один аккаунт.
  Для филиалов — отдельные инстансы (см. `docs/ATS_HOW_IT_WORKS.md` §15).
- **«А если токен протух?»** — долгосрочный токен приватной интеграции не требует
  обновления; OAuth-режим обновляет пару сам и сохраняет её атомарно (refresh
  одноразовый — поэтому сохранение обязательно).
- **«Кто такой `call_responsible`?»** — имя сотрудника (строка) для аналитики звонков;
  берётся из `provider.user` оператора связи, если он есть в событии.
- **«Почему исходное время звонка, а не время пуша?»** — `created_at` пишется из
  `calls.started_at`, чтобы аналитика amoCRM не съезжала при ретраях outbox.
- **«Что с 152-ФЗ?»** — АТС не звонит без `consent` и снимает с очередей по «не звонить»;
  в CRM уходит результат звонка, а не запись разговора целиком (доступ к записям —
  авторизованный API АТС).
