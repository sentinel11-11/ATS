## Фаза 2 — измерения и single-tenant production readiness (этап F аудита)

1. **Нагрузочные тесты** (`tools/loadtest/`): сценарии и SLO описаны,
   **запусков на стенде не было**. Цели для первого прогона (предложение,
   не заявление о ёмкости): 5 000 пользователей, 500 активных сессий,
   100 SSE, p95 обычных API < 300 мс, error rate < 0.1%, отсутствие роста
   RAM. Телефония: симулятор 10/25/50/100 каналов, затем live-стенд в
   рамках разрешений оператора.
2. **Живой стенд телефонии**: чек-листы `LIVE_TEST_MEGAFON.md`,
   `docs/MULTICOM_SETUP_STEPS.md`; фиксация реальных ограничений оператора.
3. **Backup/restore репетиция** на копии данных (`deploy/backup.sh` +
   восстановление + `python3 -m unittest` против восстановленной БД).
4. **Мониторинг/алерты**: exposition-эндпоинт метрик (глубина inbox, outbox
   backlog, активные каналы, длительность тика, SSE-подписчики) → Prometheus
   или минимальный JSON-health; структурные логи; ротация.
5. **Транзакции на оставшихся составных операциях**: campaign start/stop,
   импорт контактов (сейчас по шагам q()).

## Фаза 3 — SaaS/multi-tenancy (этап E аудита)

Решение о топологии — `docs/adr/0001-tenancy.md` (по умолчанию:
изолированный инстанс на клиента + миграция на PostgreSQL как первый шаг
shared-модели). Порядок при выборе shared:

1. PostgreSQL + пул + версионированные миграции (Alembic или эквивалент);
   адаптер SQLite остаётся для стенда/тестов.
2. `tenants`, `users.tenant_id`, tenant-контекст из проверенной сессии
   (никогда — из тела запроса).
3. `tenant_id` во всех tenant-owned таблицах + scoped repository-слой
   (не ручная правка сотен SQL).
4. Tenant-scoped настройки/секреты/провайдеры/пулы номеров/записи/лимиты.
5. Роли platform_admin/tenant_admin/operator + серверная авторизация на
   каждый объект/маршрут.
6. Общие rate limiter/сессии-лимиты (Redis), распределённый планировщик,
   lease/lock заданий, защита от двойного дозвона.
7. Object storage для записей; отдельная проверка прав на скачивание.
8. Negative-тесты межtenant-доступа на каждый маршрут/экспорт/действие.

## Техдолг (P2)

- UTC-таймстампы + IANA-часовые пояса tenant'ов (сейчас локальные строки;
  DST-границы и отчёты по нескольким регионам некорректны).
- Разбиение `app/api.py` (1963 стр.) и `app/engine.py` (~1700 стр.) на
  routers/services/workers — поэтапно, без массовой переписи, с сохранением
  HTTP-контрактов.
- HttpOnly-cookie вместо localStorage-токена (после CSP-замера).
- Версионированные миграции вместо `_migrate()` (обязательны при переходе
  на PostgreSQL).
- Включить `dependencies-audit` CI-джобу блокирующей после настройки
  exemptions (PyInstaller и пр.).
