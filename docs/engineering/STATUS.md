## Известные ограничения (не «зелёные», честно)

- Лимиты входа/SSE и кэш сессий — in-process: несколько реплик API без
  общего лимитера/хранилища не поддерживаются (нужен Redis/gateway — ROADMAP).
- SQLite, одно соединение, сериализация под RLock: горизонтального
  масштабирования нет; для shared SaaS — PostgreSQL (ADR-0001).
- Timestamps — локальные строки `%Y-%m-%d %H:%M:%S`, не UTC (ROADMAP).
- Нагрузочные инструменты есть (`tools/loadtest/`, smoke в песочнице:
  API 0 ошибок при ~190 rps, p95≈5 мс; SSE 30/30 живы), но это НЕ
  Capacity-заявление: полноценный нагрузочный и живые телефонные
  испытания на стенде не проводились (ROADMAP, фаза 2).
- Остаточные риски повторного ревью (честно):
  - amoCRM-дедуп задач — best-effort (маркер + поиск открытых задач):
    при недоступности поиска повтор может создать дубль задачи;
  - идемпотентность вебхуков по event_key покрывает generic-события
    (UIS/разрешённые МегаФон/Мультиком); события с одинаковым смыслом,
    но разными нормализованными payload без call_id не различаются;
  - CSV/Bitrix24-драйверы CRM не имеют серверного дедупа задач
    (маркер в выводе, дубли гасятся только idem_key outbox);
  - UTC-миграция timestamps не выполнена (локальные строки — ROADMAP).
- Токен сессии хранится в localStorage (XSS-риск смягчён CSP/nosniff,
  перевод на HttpOnly-cookie — ROADMAP).
- История git содержит старые скомпрометированные значения — 472 попадания
  сканера + blob'ы `data_v2/ats.db` и `initial_credentials.txt` (см.
  `docs/engineering/HISTORY_CLEANUP.md`): ротация кредов обязательна,
  filter-repo — по решению владельца (P0, единственный нерешённый пункт
  повторного ревью, требующий действий вне репозитория).
